# LearnUI 内容平台化 PRD

> 状态：Draft · 版本：v1.0 · 日期：2026-08-18

## 1. 背景与目标

LearnUI 当前以 UI 元素和视觉风格词典为核心，已经解决“看见但叫不出名字”的问题。下一阶段将其升级为面向 AI Builder 的产品与技术概念知识库：用户不仅能找到术语，还能理解概念、复制真实需求、保存和继续探索。

### 产品目标

1. 内容从 UI 元素扩展至产品、技术栈、设计风格、AI、Git 六个一级领域。
2. 每个词条都可被搜索引擎收录、直接访问和分享。
3. 让用户快速判断各分类的内容规模与覆盖范围。
4. 把“知道名称”进一步转化为“能准确要求 AI 实现”。
5. 形成低门槛贡献、可追踪审核、稳定发布的社区内容循环。
6. 通过热门、历史和关联推荐提升复访与连续阅读。

### 非目标

- 首期不建设账号系统、积分系统和站内评论。
- 首期不开放用户直接修改生产数据。
- 不复制第三方站点的受版权保护内容；新增内容必须原创或明确标注来源。
- 不在首期建设通用 CMS，内容仍以 Git 版本控制为准。

## 2. 用户与核心任务

| 用户 | 典型任务 | 成功标准 |
| --- | --- | --- |
| AI Builder | 不知道一个产品或技术概念的准确名称 | 30 秒内通过大白话搜索定位词条 |
| 开发者 | 需要让 AI 实现某种功能 | 一键复制可执行的真实需求示例 |
| 设计师 | 想理解 UI、风格和产品术语间的关系 | 能沿相关词条连续探索 |
| 搜索访客 | 从搜索引擎进入单个词条 | 页面独立可读并能继续浏览分类 |
| 社区贡献者 | 补充或纠正词条 | 5 分钟内提交结构化贡献 |
| 维护者 | 审核贡献并发布 | 能检查结构、重复、来源和双语完整性 |

## 3. 信息架构

一级领域固定为：

| key | 中文名 | 示例分类 | 示例词条 |
| --- | --- | --- | --- |
| `ui` | UI 元素 | 表单、导航、反馈、布局 | Tooltip、Skeleton |
| `product` | 产品 | 增长、商业化、协作、指标 | Onboarding、Activation |
| `stack` | 技术栈 | 前端、后端、数据、云服务 | React、PostgreSQL |
| `style` | 设计风格 | 视觉语言、排版、动效 | Brutalism、Glassmorphism |
| `ai` | AI | 模型、Agent、RAG、评测 | Embedding、Tool Calling |
| `git` | Git | 基础、分支、协作、恢复 | Rebase、Cherry-pick |

导航规则：一级领域显示词条总数；进入领域后显示二级分类及数量；筛选结果数量实时更新，但导航中的总量不随当前筛选变化。

## 4. 功能需求

### F1 内容领域扩展

- 顶部导航提供六个一级领域入口，并保留全站搜索。
- 词条必须包含领域、分类、名称、别名、摘要、正文、真实需求示例和关联词条。
- 首次发布每个新增领域至少 15 个词条；低于该数量的领域标记为 Preview。
- 中英文内容字段保持结构一致，允许某些专有名词共用英文名称。

验收标准：

- 可按领域和二级分类筛选。
- 搜索覆盖名称、别名、摘要、用户口语描述和关键词。
- 领域数量、分类数量和实际数据一致。

### F2 词条独立 URL、分享与 SEO

- 路由格式：`/:lang/:domain/:slug`，示例 `/zh/ai/tool-calling`。
- 旧首页弹窗打开词条时同步更新 URL；关闭后恢复来源列表 URL。
- 直接访问词条 URL 时渲染完整详情页，不依赖来源页状态。
- 每页输出唯一 `title`、description、canonical、Open Graph、Twitter Card 和 JSON-LD。
- 生成 `sitemap.xml`、`robots.txt`，并提供不存在词条的 404 页面。
- slug 变更通过显式 redirect 映射保持旧链接可用。
- 分享动作支持复制链接；浏览器支持时调用 Web Share API。

验收标准：URL 可刷新、前进后退、直接打开和分享；中英文页面互设 `hreflang`；社交预览信息正确。

### F3 分类数量

- 一级领域展示总词条数，二级分类展示对应数量。
- 收藏、热门等个性化入口展示动态数量。
- 数量由构建期从内容源计算，禁止手写。
- 过滤后在结果区显示“当前显示 N / 共 M 条”。

### F4 可复制的真实需求示例

每个词条至少提供一个 `promptExample`，结构为：

1. 场景：用户正在解决什么问题。
2. 要求：AI 应实现的行为与边界。
3. 验收：如何判断输出可用。

示例必须具体、可执行，避免“做得更好看”一类空泛表述。复制按钮提供成功反馈并保留原有语言；可选“精简版 / 完整版”时默认完整版本。

### F5 社区贡献与审核

- 全站提供“贡献词条”入口，链接至 GitHub Issue Form。
- 表单字段：领域、分类、名称、别名、大白话描述、正文、真实需求示例、参考来源、关联词条、语言、贡献类型。
- 支持新词条、内容纠错、翻译补充和来源更新四种贡献类型。
- GitHub Actions 将表单转为校验结果：必填字段、重复 slug、链接可访问性、双语完整性和格式。
- 维护者将合格 Issue 转为内容 PR；至少一名维护者审核后合并。
- 贡献状态：`needs-triage` → `needs-content-review` → `needs-technical-review` → `ready` / `rejected`。

审核原则：名称准确、解释原创、来源可信、示例可执行、关联合理、双语一致。

### F6 热门、最近浏览和相关推荐

- 热门：匿名聚合词条浏览事件，展示 7 天与 30 天榜单；首期没有分析数据时使用构建期固定 `featuredRank` 降级。
- 最近浏览：浏览器本地保存最近 20 条，按最后访问时间倒序，可一键清空。
- 相关推荐：每个详情页展示 3–6 条，优先级为显式关联 > 同分类标签相似 > 同领域热门。
- 不记录用户输入的搜索原文，不在本地记录敏感信息。

## 5. 核心指标

- 词条详情页自然搜索访问量。
- 搜索无结果率与搜索后打开词条率。
- 真实需求示例复制率。
- 每次会话查看的词条数与相关推荐点击率。
- 7 日回访率、收藏使用率、最近浏览使用率。
- 每月有效社区贡献数与贡献通过率。

## 6. 上线门槛

- 所有新路由支持移动端、键盘导航及中英文切换。
- Lighthouse SEO ≥ 95，Accessibility ≥ 90。
- 内容构建校验零错误；不存在重复 slug 和悬空关联。
- sitemap 包含全部可索引词条，草稿不进入生产构建。
- 埋点失败不得阻塞页面渲染或交互。
