# LearnUI 词条贡献与审核指南

## 贡献类型

- 新词条：补充当前没有覆盖的概念。
- 内容纠错：修正名称、解释、示例或平台信息。
- 翻译补充：补全或改进中英文版本。
- 来源更新：替换失效链接或增加更权威的一手资料。

## 合格词条的标准

1. **名称准确**：优先采用标准、官方文档或行业广泛使用的名称。
2. **解释原创**：用自己的语言说明，不大段复制来源。
3. **范围清楚**：解释它是什么，也说明它不是什么或易混淆概念。
4. **示例可执行**：真实需求示例必须包含场景、行为和验收条件。
5. **来源可信**：技术概念优先官方文档、规范和原始论文。
6. **关联合理**：只关联能帮助对比或继续学习的词条。
7. **双语一致**：两种语言表达可以自然不同，但事实和范围必须一致。

## 提交流程

1. 搜索名称和别名，确认没有重复词条。
2. 通过“贡献词条”Issue Form 提交结构化信息。
3. 自动检查给出格式、重复项和缺失字段提示。
4. 维护者进行内容审核，必要时要求补充来源或缩小范围。
5. 合格 Issue 转换为内容 PR，完成技术校验和双语检查。
6. 合并后随下一次部署发布，并在词条中记录贡献者。

## 审核清单

- [ ] domain 与 category 选择合理。
- [ ] id、slug 唯一且符合命名规范。
- [ ] 名称和 aliases 能覆盖常见叫法。
- [ ] plainQueries 使用用户真的会输入的大白话。
- [ ] summary 独立阅读即可理解。
- [ ] promptExample 不依赖隐藏上下文且包含验收标准。
- [ ] relatedIds 存在且关系有意义。
- [ ] sources 至少包含一个可信来源。
- [ ] 中英文事实一致，没有遗漏 UI 文案。
- [ ] 内容不存在版权、隐私或安全风险。

## 拒绝或暂缓的情况

- 仅为某家产品的短期营销词，没有普遍学习价值。
- 无法确认名称或来源，且可能误导用户。
- 与现有词条重复，只是措辞不同。
- 内容大量复制第三方材料。
- 示例要求绕过安全、权限或平台限制。
- 范围过大，无法在单个词条中清楚解释。
